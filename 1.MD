### 1.2 Run the photo archive once

`scripts/mirror-photos.mjs` is written, rehearsed and **never run for real**,
because no Blob store exists yet.

```
# Vercel dashboard -> Storage -> Create -> Blob, then copy the read-write token
export BLOB_READ_WRITE_TOKEN=...
node scripts/mirror-photos.mjs --dry --limit 30   # rehearse
node scripts/mirror-photos.mjs                    # the real run
```

Measured on a 30-file dry run: **~664MB for the whole catalog**, storage only -
nothing serves from it, so there is essentially no bandwidth. That is cents a
month. It is resumable and safe to re-run; run it after each data session so
new photographs get a copy while they are still alive.

**Two corrections to what the old version of this file said.** It estimated
450MB - the real figure is higher because the archive takes the widest width
the source actually permits. And it proposed serving from the mirror: that
would have cost the responsive srcSet (~150KB to a phone that gets ~60KB
today), and more fundamentally **you cannot mirror a URL after it dies** - once
Commons deletes a file the bytes are gone. So this is an archive, Commons stays
the thing browsers talk to, and the rendering path is untouched.

## 5. Traps worth remembering

- **`git am --abort` is not a cleanup.** A stale `am` session was sitting in
  `.git` from a session months ago; aborting it would have reset `main` to a
  commit from 30 July and destroyed two months of history. Check
  `.git/rebase-apply/abort-safety` against `HEAD` before touching it - and if
  the patches are already merged, just delete the directory.
- **A rate limit is not an absence.** Wikimedia answered 429 for 11 of 30 files
  during the archive's first run and the script recorded them as dead. Only
  404/410 is death; everything else backs off. The same lesson is already in
  the log from a geosearch pass, which is the point.
- **Satori has no bidi pass.** `next/og` renders Hebrew mirrored, and
  `direction: rtl` does not fix it - it only right-aligns. Anything drawn with
  `ImageResponse` must go through `lib/og/bidi.ts` first. And do not settle it
  by reading the rendered image: put Chrome's rendering of the same string
  directly above it, because reading the picture nearly passed a mirrored card
  as correct.
- **`fetch` cannot read `file://` in the Node runtime.** The
  `fetch(new URL('./font.woff', import.meta.url))` shape the Next docs show is
  an Edge-runtime pattern; here it throws "not implemented... yet..." and
  surfaces as a bare 500 with no other clue. Locate with `import.meta.url` so
  the bundler emits the asset, read with `fs`.
- **Declaring `openGraph.images` suppresses `opengraph-image.tsx`.** The
  generic `/og.png` in the page's metadata was actively preventing a per-trip
  card, which looks like the file convention not working.
- **Animations do not advance in this headless browser.** Every animation
  reports `playState: running` with `currentTime: 0`, so `fill: both` pins
  elements at their *from* state forever. Any measurement of an animated
  element here is unreliable.
- **Kill a dev server by port, not by name.** `pkill -f "next start"` matches
  nothing on Windows; `netstat -ano | grep :3123` then stop the pid.
- **A stale `.next/types/validator.ts` fails `tsc` after a branch switch.**
  Delete `.next/types` and re-run; it is not a source error.
- **Backticks in a bash heredoc are command substitution**, and a bash command
  over ~8k characters is truncated by the OS and fails as "unexpected EOF".
  Use the Write tool for anything long or containing backticks or regex.
- **`grep -c` returning 0 exits non-zero** and will break an `&&` chain.
